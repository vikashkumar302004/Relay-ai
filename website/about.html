Why Relay exists.

AI tools are powerful, but the work around them is still fragmented. A useful conversation can stop because a limit is reached, a different model is better for the next task, or the right context is trapped in another tab.

Relay began with one practical question: why should people have to explain the same project again every time they move to another AI?

Vikash built Relay as a continuity layer that sits inside the tools people already use. It turns the useful parts of a visible conversation into a compact handoff, lets the user review it, and carries it to the next provider.

“The AI can change. The work should continue.”

The project is intentionally local-first. Relay does not need provider API keys, does not collect account passwords and never sends a message without the user choosing to do it. The goal is not to replace Claude, ChatGPT, Gemini or Perplexity—it is to make them work better together.

HOW IT IS BUILT

Three principles.
One continuous thread.

01 · USEFUL

Remove repeated work

Every feature should save a real step: less copying, less re-explaining and a faster return to the task.

02 · PRIVATE

Keep users in control

Context stays in the browser. Users review every handoff and decide exactly what gets inserted or sent.

03 · OPEN

Work across providers

Relay is designed around the user's workflow—not around locking the user into a single AI company.
